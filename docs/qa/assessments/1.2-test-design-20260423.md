**说明**：Story 1.2 首次引入业务表 `users` + 认证型流程（短信验证码 + 唯一手机号），具备"身份创建 + 敏感数据 + 外部服务降级"三重风险轴。P0 聚焦于：
1. **安全专项**（验证码一次性消费、重放防护、频率限制原子性、敏感数据不外溢、注入防护）
2. **数据完整性**（唯一约束兜底、事务回滚、Redis 与 DB 的先后语义）
3. **响应契约**（HTTP 200 + `R.code` 统一契约，Architect Round 2 M1/M2/M3 修订产物验证）

E2E 保持 "Phase C Smoke Test 再补齐"（沿用 1.1 `smoke-test` 策略）。
